# Agent 2 Review Workflow Specification

## States

### draft_pending
- **Description**: Initial email draft generated by Agent 2
- **Trigger**: Successful email generation from handoff packet
- **Visibility**: Visible to human reviewer
- **Actions**: Human can approve, reject, or request changes

### draft_reviewing
- **Description**: Human reviewer is actively reviewing the draft
- **Trigger**: Human opens draft for review
- **Visibility**: Draft marked as "in review"
- **Actions**: Human can approve, reject, or provide feedback

### draft_approved
- **Description**: Email draft approved by human reviewer
- **Trigger**: Human clicks "approve" action
- **Visibility**: Ready for sending or final processing
- **Actions**: Draft can be sent to prospect or archived

### draft_rejected
- **Description**: Email draft rejected by human reviewer
- **Trigger**: Human clicks "reject" action
- **Visibility**: Marked for regeneration
- **Actions**: Triggers Agent 2 regeneration with feedback

### draft_regenerating
- **Description**: Agent 2 is regenerating the email draft
- **Trigger**: Automatic after rejection with feedback
- **Visibility**: System processing state
- **Actions**: New draft generation in progress

### draft_failed
- **Description**: Maximum revision attempts exceeded
- **Trigger**: revision_count reaches max_revision_count
- **Visibility**: Requires manual human intervention
- **Actions**: Human must manually create or approve draft

## Transitions

### pending → reviewing
- **Condition**: Human reviewer opens draft for review
- **Action**: Set status to "draft_reviewing"
- **System**: Mark draft as "in review" state

### reviewing → approved
- **Condition**: Human reviewer clicks "approve" button
- **Action**: Set status to "draft_approved"
- **System**: Record approval timestamp and reviewer

### reviewing → rejected
- **Condition**: Human reviewer clicks "reject" button
- **Action**: Set status to "draft_rejected"
- **System**: Store rejection reason and trigger regeneration

### rejected → regenerating
- **Condition**: Automatic transition after rejection
- **Action**: Set status to "draft_regenerating"
- **System**: Increment revision_count and start new generation

### regenerating → pending
- **Condition**: Successful new draft generation
- **Action**: Set status to "draft_pending"
- **System**: Present new draft for human review

### regenerating → failed
- **Condition**: revision_count exceeds max_revision_count
- **Action**: Set status to "draft_failed"
- **System**: Lock workflow until manual intervention

## Constraints

### Revision Limits
- **max_revision_count**: 3
- **Purpose**: Prevent infinite regeneration loops
- **Behavior**: After 3 failed attempts, workflow stops

### Human Review Requirement
- **requires_human_review**: true (hard rule)
- **Purpose**: Ensure human oversight on all outreach
- **Behavior**: No draft can be sent without human approval

### Feedback Integration
- **rejection_reason**: Optional text from human reviewer
- **Purpose**: Guide Agent 2 to avoid repeated mistakes
- **Behavior**: Included in regeneration context

## Approval Flow

### Human Review Interface
1. **Draft Display**: Show email subject, body, and metadata
2. **Quality Indicators**: Display phrase warnings, confidence scores
3. **Context Information**: Show packet insights and personalization hooks
4. **Binary Decision**: Approve or Reject buttons

### Approval Action
- **Trigger**: Human clicks "Approve"
- **Result**: Status changes to "draft_approved"
- **System Actions**:
  - Set `approved_at` timestamp
  - Record `reviewed_by` (future: user_id)
  - Archive approved draft
  - Update `draft_status` to "approved"

### Rejection Action
- **Trigger**: Human clicks "Reject"
- **Result**: Status changes to "draft_rejected"
- **System Actions**:
  - Capture optional `rejection_reason` text
  - Increment `revision_count`
  - Trigger regeneration workflow
  - Update `draft_status` to "rejected"

## Regeneration Logic

### Context Preservation
- **Original Packet**: Maintain Agent 1 handoff packet context
- **Previous Draft**: Include rejected draft for reference
- **Rejection Reason**: Use human feedback to avoid repeated errors
- **Quality History**: Track phrase violations and corrections

### Mistake Avoidance
- **Phrase History**: Remember which phrases caused rejections
- **Pattern Recognition**: Identify recurring quality issues
- **Adaptive Generation**: Adjust approach based on feedback
- **Quality Gate Compliance**: Ensure new draft passes all validation

### Revision Counting
- **Increment Logic**: `revision_count += 1` per regeneration
- **Maximum Check**: Stop at `max_revision_count = 3`
- **Failure State**: Transition to "draft_failed" when limit reached

## Audit Fields

### Core Status Fields
- **draft_status**: Current workflow state (pending, reviewing, approved, rejected, regenerating, failed)
- **revision_count**: Number of regeneration attempts (0-3)
- **approved_at**: ISO timestamp when draft was approved
- **reviewed_by**: User ID of human reviewer (future implementation)

### Draft Content Fields
- **latest_email_draft**: Complete JSON of current draft
- **previous_drafts**: Array of rejected drafts for audit trail
- **rejection_reasons**: Array of human feedback for each rejection

### Quality Tracking
- **phrase_violations**: Array of detected banned/soft warning phrases
- **quality_scores**: Confidence and trust metrics from packet
- **improvement_history**: Track quality improvements across revisions

## Workflow Integration

### Database Storage
- **Draft Records**: Store each draft with full audit trail
- **Status Updates**: Log all state transitions with timestamps
- **Human Actions**: Record approval/rejection decisions

### UI Integration
- **Status Display**: Show current workflow state clearly
- **Action Buttons**: Enable appropriate actions based on current state
- **History View**: Display revision history and feedback

### Automation Boundaries
- **Human Required**: No automatic sending without approval
- **Quality Enforcement**: Phrase gate and validation always active
- **Failure Handling**: Clear escalation path for failed workflows

## Implementation Notes

### State Management
- Use deterministic state transitions
- Maintain audit trail for all changes
- Ensure atomic state updates

### Error Handling
- Graceful handling of missing fields
- Recovery from interrupted workflows
- Clear error messages for human users

### Performance Considerations
- Efficient draft storage and retrieval
- Fast status updates and transitions
- Minimal database queries for workflow operations
